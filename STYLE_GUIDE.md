# Style Guide

## CSS/SCSS Class Naming

We use a simple namespace-container pattern to scope component styles:

### `nsc-` Prefix (Namespace Container)

The `nsc-` prefix is **only used on the top-level element** of a component. It creates a contained style scope for that component.

**Nested elements within the component do NOT use the `nsc-` prefix.**

#### Example:

```scss
// ✓ Good
.nsc-modal {
  border: none;
  background: white;

  .modal-content {
    padding: 2rem;
  }

  .modal-close {
    position: absolute;
    cursor: pointer;
  }
}
```

```scss
// ✗ Bad
.nsc-modal {
  .nsc-modal-content {  // Don't use nsc- on nested elements
    padding: 2rem;
  }

  .nsc-modal-close {    // Don't use nsc- on nested elements
    cursor: pointer;
  }
}
```

### Benefits

- **Clear scoping**: Only the root element is namespaced
- **Cleaner nesting**: Child selectors are simpler
- **Less verbose**: Reduces repetition in class names
- **Easier maintenance**: Changes to the namespace only affect one place

### Usage in Components

```tsx
// modal.tsx
export function Modal({ children }: { children: React.ReactNode }) {
  return (
    <dialog className="nsc-modal">
      <div className="modal-content">
        <button className="modal-close">✕</button>
        {children}
      </div>
    </dialog>
  );
}
```

### No BEM `--` modifiers

Do **not** use double-dash BEM modifier classes (`box--left`, `card--active`).
For a variant of an element, use a plain second class; for state, use an `is-`
class. This keeps naming consistent with the `nsc-` pattern above, which leans on
plain, parent-scoped child names rather than encoded modifiers.

```tsx
// ✓ Good — plain variant class + is- state
<div className="composition-box composition-left">…</div>
<button className="nav-link is-active">…</button>

// ✗ Bad — BEM-style -- modifiers
<div className="composition-box composition-box--left">…</div>
<button className="nav-link nav-link--active">…</button>
```

### Multi-word class names are hyphenated

Join the words in a class name with a hyphen: `section-title`, not
`sectiontitle` or `sectionTitle`. Two words run together read as one unfamiliar
word and have to be parsed letter by letter, which is the opposite of what a
name is for; camelCase gets lost the moment a selector is typed in lowercase.

This is the one naming rule the others did not cover, so it is the one that
keeps slipping through. A hyphen inside a name is not a BEM element or a BEM
modifier - those are the double `__` and `--` forbidden above - and a single
hyphen is free to use.

```tsx
// ✓ Good
<h2 className="section-title">…</h2>
<div className="scene-row is-active">…</div>

// ✗ Bad — run together, or camelCased
<h2 className="sectiontitle">…</h2>
<h2 className="sectionTitle">…</h2>
```

## Prefer a CSS class over a new component

When an effect is **purely visual** — a background, texture, decorative layer,
gradient, border treatment, shadow, etc. — and adds no markup, state, or
behaviour of its own, expose it as a **drop-in CSS utility class**, not a React
wrapper component.

Adding the class to any element should be all it takes to get the effect:

```tsx
// ✓ Good — drop-in class, works on any element
<section className="home-events has-splatter-bg">…</section>
```

```scss
// has-splatter-bg lives once in globals; add it anywhere.
.has-splatter-bg {
  position: relative;

  // Decorative layer sits behind content so opacity/stacking never
  // touch the children. Tune with a custom property, not a prop.
  &::before { content: ""; position: absolute; inset: 0; z-index: 0; opacity: var(--splatter-opacity, 0.55); /* … */ }
  > * { position: relative; z-index: 1; }
}
```

```tsx
// ✗ Bad — a wrapper component that only renders a styled element
<SplatterBackdrop as="section" className="home-events">…</SplatterBackdrop>
```

Why:

- **Less indirection** — no extra file, import, or `as`/`className` plumbing to
  forward; the markup reads as plain HTML.
- **Composable** — stacks freely with other classes on the same element and
  works on any tag without a polymorphic `as` prop.
- **Parameterise with CSS custom properties** (`style={{ "--splatter-opacity": 0.35 }}`),
  not component props.

Reach for a component **only** when the thing carries its own markup, children
structure, state, or behaviour. A class that exists purely to set styles does
not justify a component.

## Responsive breakpoints

Use the shared mixins from `app/styles/_breakpoints.scss` — don't hand-write
`@media (min-width: …)` / `(max-width: …)` for the standard breakpoints. Import
the partial with `@use` (not the deprecated `@import`):

```scss
@use "@/app/styles/breakpoints" as *;

.thing {
  @include respond-to("tablet")     { … }  // min-width — "tablet and up"
  @include respond-to-max("tablet") { … }  // max-width — "below tablet"
}
```

`respond-to-max` sits 0.02px under the breakpoint so it never overlaps the
min-width `respond-to` at the same value.

### Show / hide by breakpoint

`.mobile-only` / `.desktop-only` each **only hide on the opposite breakpoint** —
they never set a "shown" `display`, so the element keeps its own display (flex,
grid, inline-block) where visible. **Never** use `display: revert` to re-show; it
clobbers a custom display.

```scss
.desktop-only { @include respond-to-max("tablet") { display: none; } }
.mobile-only  { @include respond-to("tablet")     { display: none; } }
```

For a divergent mobile/desktop layout, render **both** variants and toggle them
with these utilities (CSS show/hide). This is the accepted approach while media
is light. Because the utilities preserve the element's own `display`, you can put
`mobile-only` / `desktop-only` directly on a flex/grid root — no wrapper needed.

## Colour tokens & units

- Reference colours via the `--color-*` custom properties in `:root`
  (`--color-ink`, `--color-muted`, `--color-line`, `--color-faint`). Don't
  hardcode hex in component styles — add a token if one is missing.
- Prefer `rem` over `px` for spacing and sizing.

---

**Key rule**: Use `nsc-` on the root element only. Nested elements are scoped by the parent and don't need the prefix. No `--` modifiers — plain classes for variants, `is-` for state. Hyphenate multi-word names (`section-title`).
