Studio shell and design tokens

The studio screen exists: toolbar, camera panel, stage, picture panel, playback bar and timeline, laid out for a tablet in landscape and adapting down to a phone. Every area is a placeholder that names the step that fills it. Colours, sizes and the font are now tokens.

What was built

  • Tokens in src/styles/globals.scss: --color-* on :root with the same names redefined for dark mode, touch sizes (--hit 56 px, --hit-big 88 px), radii, a 4-step spacing scale, the timeline height.
  • Breakpoints in src/styles/_breakpoints.scss: respond-to() / respond-to-max() mixins and the .desktop-only / .mobile-only utilities from the workspace style guide.
  • Button classes in src/styles/_controls.scss: .icon-button and .big-button with is-capture / is-play variants.
  • Font: Nunito through next/font/google, exposed as --font-ui.
  • /studio: src/app/studio/page.tsx (server component with a <Suspense>) renders src/studio/Studio.tsx (client component) and studio.scss.
  • Home (/): a "Start animating" button to the studio and a link to these notes. It becomes the projects list in step 08.
  • lucide-react for icons.

Decisions

One client boundary at the studio root

Studio.tsx starts with "use client"; the route file stays a server component that only wraps it in <Suspense>. Almost everything in the studio is interactive and browser-only (camera, canvas, IndexedDB), so splitting server and client components inside it would gain nothing.

The project id is a query param, read in the client

/studio?project=abc, read with useSearchParams(). A static export can't pre-render a /studio/[id] page for ids that only exist in the user's browser. Reading search params forces that component to render on the client, and Next requires a <Suspense> boundary above it; the fallback is null because the shell appears almost instantly anyway.

Markup stays in one file for now

The six areas are plain markup inside Studio.tsx, not six components. They have no behaviour yet, and the workspace rule is "no abstraction layers": each area becomes its own component in the step that gives it state (CameraPanel in 03, Timeline in 05/09, and so on). The two side panels repeat their few lines of markup instead of sharing a Panel wrapper.

Buttons are classes, not components

.icon-button and .big-button only style a <button> or <Link>; they add no markup or behaviour. Per the style guide, that makes them drop-in classes, so they work on any element without a polymorphic as prop.

The stage keeps 16:9 with container units

The stage cell is a size container (container-type: size), and the frame inside is width: min(100cqw, 100cqh * 16 / 9) with aspect-ratio: 16 / 9. That's "fit inside, keep the ratio" in one line, at every layout, with no resize listener. When projects get other sizes, the ratio becomes a custom property.

Kid-sized and kid-worded

  • Smallest touch target 56 px, capture and play 88 px, with a "pressable" shadow that moves on :active.
  • One loud colour (red, for capture), green for play, everything else calm.
  • Plain words in the UI: "Pictures", "Speed", "See-through", "Save as video".
  • Nunito: rounded and friendly, but still clear at small sizes. next/font downloads it at build time and serves it from the app, so there's no request to Google when a child uses it, and it works offline later.

The stage is dark in both themes

Photos read best on a neutral dark backdrop, the way photo and video editors do it. In dark mode the stage is darker than the page and has an outline, so the frame still stands out.

Watch out

  • Grids and long content. A plain 1fr column grows to fit its widest child, so the scrolling timeline strip pushed the phone layout to twice the screen width. Columns are minmax(0, 1fr), which lets them shrink and makes the strip scroll inside its box instead.
  • useSearchParams without <Suspense> fails next build with a static export. Keep the boundary in page.tsx.
  • Icon-only buttons need a name. When a label is hidden on phones (desktop-only), the button keeps an aria-label so screen readers still announce it.
  • Sass modules. Use @use "@/styles/breakpoints" as *; (not @import), and map.get from sass:map (not the deprecated global map-get).
  • Global CSS per area. studio.scss is a global stylesheet imported by Studio.tsx; the nsc-studio root is what scopes it. Don't add top-level selectors to it.
  • Vitest's native binary disappeared again when lucide-react was installed, so the step 00 workaround (clean reinstall) wasn't enough. @rolldown/binding-win32-x64-msvc is now pinned in optionalDependencies at rolldown's exact version (1.2.19); see step 00's notes.
  • On a phone the project name truncates ("My ...") next to four toolbar buttons. Fine for a placeholder; step 29 revisits phone toolbars.

Check it

npm run dev
  • / shows the start button; it opens /studio.
  • /studio?project=abc says "My animation", /studio says "New animation".
  • Resize from desktop to 768 px to phone width: three columns, then panels under the stage, then panels hidden. No sideways scroll at any width.
  • Switch the OS to dark mode: everything follows, and the stage still stands out.
  • npm run build lists /studio as static (○).
