Build steps · Step 26 · Part 9 Export and import

Video export

Save as video in the toolbar, beside Save as GIF, makes a video of the animation and downloads it. It's an MP4 (H.264) where the browser can make one, otherwise a WebM (VP9).

  • The video is what's inside the dotted line, at its full size (1208 × 680 for a 1280 × 720 animation, 16:9). It has every picture for as long as it's held, with its objects and the overlays showing at the time. There's no sound.
  • While it's made, the button shows how far it got, and a cross stops it, as for the GIF. Afterwards a note says it was saved.
  • Where the browser can make neither format, there's no button. The browser is asked (WebCodecs), not guessed from its name.

What was built

  • One plan for both exports, src/core/export/segments.ts: exportSegments cuts the animation where the screen changes (moved out of gifFrames, which now uses it), and exportFileName.
  • The video's timing, src/core/export/video.ts: videoFrames, one video frame per segment with its start and length in seconds. They're worked out from ticks each time, so they don't drift.
  • Encoding, src/adapters/export/videoExport.ts, with Mediabunny:
    • videoFormat picks the first of VIDEO_FORMATS (MP4 then WebM) that the browser can encode at this size;
    • exportVideo draws each frame through drawExportFrame onto a canvas that a CanvasSource reads, waiting while the encoder catches up. It reports progress, stops on an AbortSignal (and cancels the file), and returns the file.
  • The button, src/features/video-export/VideoExportButton.tsx, placed by Studio.tsx beside Save as GIF.
  • Shared by both buttons, as planned in the step 25 review:
    • src/studio/useExport.ts: one file at a time, progress, stopping, the note afterwards, stopping when the studio closes, and download. GifExportMenu now uses it.
    • src/studio/styles/_export.scss: the progress bar and the note, for any .export-menu.
  • The design page's toolbar shows both buttons. New dependency: mediabunny 1.65.1 (MPL-2.0), pinned exactly.

Decisions

  • A held picture is one frame with a long duration, not copies of it (the roadmap's plan). The file is smaller and quicker to make, and players handle it.
  • MP4 first. MP4 with H.264 plays in every player and chat app. WebM with VP9 is the fallback, for browsers without an H.264 encoder.
  • Full size only. A video compresses far better than a GIF, so there are no size or quality options yet. Mediabunny's "high" quality sets the bitrate.
  • Drawn on the page, encoded by the browser. WebCodecs already encodes off the page's thread, so there's no worker of our own.
  • Mediabunny 1.65.1, not the newest (1.66.0), which was five days old. It's MPL-2.0: using it unchanged is fine; changes to its own files would have to be shared.
  • No exporters list yet (PLAN.md §4). The two buttons share useExport; a list or a single "Save as…" menu can come with the archive (27).

Watch out

  • Browsers differ: Playwright's Chromium makes MP4s; Safari and Firefox support varies by version. The button only shows where a format can be encoded, and only WebKit was left untested (the full suite wasn't run).
  • Very long holds: a frame many seconds long is valid. Players that jump to a time start from the last key frame, so the first jump into a long hold can take a moment to show.

Check it

  • Take a few pictures, hold one longer, add a title on the overlay track, and Save as video. Open it in the computer's own player: the timing matches playback, the title shows when it should, and the edges are what's inside the dotted line.
  • Start a long one and press the cross: it stops, and nothing is downloaded.

Review checklist

  • the video is what's inside the dotted line, at full size, as long as playback
  • a held picture is one frame; MP4 where possible, WebM otherwise, no button when neither
  • progress and stopping work as for the GIF (one useExport)
  • the timing is plain maths in core, shared with the GIF
  • npm test, npm run test:browser, npm run lint, npm run typecheck, the build and export.spec pass
