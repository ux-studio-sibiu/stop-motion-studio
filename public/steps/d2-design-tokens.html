Build steps · Step D2 · Part 8b Design system page

One list of tokens

Every design token is now in one list, src/design-system/tokens.ts, with its group, kind, light and dark values and what it's for. A test holds it to globals.scss, and the gallery's token section draws from it. Values that were written straight into the stylesheets became tokens first, so there's more to tune in D3.

New tokens

  • Text sizes, smallest first: --text-tiny, -caption, -label, -hint, -small, -body, -title, -heading. 33 literal sizes in the stylesheets now use them, with identical values; one-off page headings stay literal.
  • Shadows: --shadow-floating (menus, notices), --shadow-dragged, --shadow-press and --shadow-pressed (a big button's depth). Nearly identical shadows were merged: the storage notice's is now the menus', the two drag ghosts share one.
  • A scrim: --color-scrim and --color-on-scrim, behind and on labels over photos (the stage note, picture numbers).
  • Left literal on purpose: the camera flash's white, the safe zone's veil and the dialog backdrop (effects, not design), and the design page's own layout.

Decisions

  • Written by hand, tested: the list carries the groups and notes the panel needs, which the SCSS can't. tokens.test.ts reads globals.scss and compares the whole list, light and dark, so a token added, removed or changed in one place and not the other fails npm test.
  • One test only, as agreed for this utility page.
