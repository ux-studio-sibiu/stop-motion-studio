Feature folders (instead of a plugin registry)

The roadmap planned a plugin registry here: features registering themselves, and the studio drawing whatever is registered. It was built, then taken out again. What stays is simpler:

  • each feature's code lives together in its own folder, src/features/;
  • the studio imports those components and places them directly in its JSX.

The studio looks and works as before, except for one move: the safe zone slider is now in the Play options, with Speed and Loop, instead of in see-through's options.

What was built

  • src/features/, one folder per feature, with the components moved from src/studio/ unchanged:
    • camera/: CameraPanel.
    • picture/: PictureControls, AdjustControls, StageEditor, transformEditing, useStagePan.
    • onion-skin/: OnionSkin, SeeThroughMenu.
  • Studio.tsx imports them from @/features/… and places them as before: the two tabs, see-through on the stage, the Picture tab's stage tool.
  • PlaybackBar takes what goes beside Play as children (the see-through button), so the studio decides what's in the bar.
  • The safe zone slider moved into the Play options (SafeZoneOption in PlaybackBar.tsx).
  • TransformChange and AdjustChange moved into useStudioCommands: the studio owns the shape of its changes, and features use it, not the other way round.
  • src/features/README.md says how features are organised.
Built, then taken out: the plugin registry.

The first version had:

  • core/plugins/registry.ts, with seven kinds: panels, stage tools, stage layers, controls, exporters, frame sources, element kinds;
  • each feature registering itself from an index.tsx;
  • the studio drawing whatever was registered.

It worked: taking an import out removed that feature cleanly. It was removed because a registry decides the layout for the features. Tabs go in the side panel, controls go after Play. Moving a piece of UI for a UX experiment then needs a new slot or a special case, where direct composition makes it a cut and paste.

It also brought a global object filled by imports, and a hot-reload quirk: a removed feature stayed registered on the dev server until it restarted. It even forced a design change, because the safe zone slider had to leave see-through's dropdown so see-through could be removed alone.

Decisions

  • Direct composition (COMPONENT_PATTERNS.md: composition over configuration, no abstraction layers). The whole layout is in Studio.tsx, readable and rearrangeable in one place.
  • Lists only where they fit: many items of one kind, shown alike. Element kinds (step 23: the renderer draws each by its kind, and an "Add" menu lists them) and exporters (step 25: rows in one "Save as" menu) will be plain arrays, not a registry.
  • Features change the animation only through the commands the studio passes them, so everything they do can be undone.
  • The safe zone stays in the Play options, with the other settings for how the video comes out (your choice).

Check it

  • Everything works as before, and the safe zone is in the Play options.
  • Removing a feature is deleting its imports and its lines in Studio.tsx; TypeScript points at anything left behind.

  • The other specs and the full suite weren't run.
