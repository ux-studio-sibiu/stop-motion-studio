Move, scale, rotate, flip

When the table or the camera gets bumped between shots, a picture no longer lines up with the ones before it. Now a child can put it back. With the camera off and a picture on the stage:

  • drag it to move it;
  • grab the round handle to turn it;
  • use the wheel to make it bigger or smaller, around the pointer.

The arrow keys nudge it one pixel at a time. The Picture tab shows the exact numbers, and has flip and reset buttons. Each gesture is one undo step.

Added after this step: the safe zone. The stage shows a 20 px band along every edge, veiled, with a dotted line (SafeZone.tsx), in every mode: live camera, picture and playing. That band is what the video leaves out. Export (steps 25-27) will crop to exportRect() in core/render/safeZone.ts, which keeps the width and height even (3 unit tests), so what's inside the line is what the file contains. Everything else keeps the whole picture: capture, the renderer, moving pictures. So nudging a picture can still bring its edge into the frame.
Changed later (after step 18):

  • The Picture tab is headed "Adjust your picture". Its hint text is gone. Size steps by 1% and Turn by 0.5°.

  • No jump on reload. The studio stays hidden until it looks as it was left: the animation is loaded with its remembered settings, and the camera is running or known to stay off. Then it fades in.   • The safe zone is set per animation, 0-60 px, with a slider in the see-through options. It's undoable and saved with the animation (safeMargin).

Decisions

Project pixels, not screen pixels

A transform stores x and y as fractions of the picture (step 02), so it survives a change of resolution. Every edit works in project pixels instead:

  • one arrow press moves the picture one pixel of the video, however big the stage is on screen;
  • ten presses are exactly ten pixels, which a test checks;
  • a drag is converted with the stage canvas's size on screen, so dragging 100 screen pixels across a small stage moves the picture more than 100 project pixels.

Sizing keeps the pointer's spot still

Making the picture bigger around its centre, while the pointer is over a toy's head, would slide the head away from the pointer. scaleAround moves the centre too, so whatever is under the pointer stays under it. Keyboard + / - size around the picture's centre. The size stays between 10% and 10×. At a limit, the centre only moves as much as the picture really grew, which a test checks.

Turning around the picture's own centre

The renderer turns a picture around its centre (step 15). The handle measures the angle from that centre to the pointer, and turns by how much that angle changed. The angle is kept between −180° and 180°.

The handle sits just inside the top edge. The first version put it above the picture, which is outside the stage frame whenever the picture fills it. The frame clips, so the handle couldn't be seen or grabbed there; the Playwright test caught it.

Preview first, one command at the end

Dragging writes to the store's preview only, and the stage redraws from it on the next animation frame, not on every pointer event. Letting go saves one setTransforms command. Arrow presses, wheel turns and typed numbers come in bursts, so they save once, 600 ms after the last one. Pressing an arrow key ten times is one undo step, and a test checks that. Escape forgets what isn't saved.

What gets edited

The selected pictures, or, if none is selected, the one on the stage (the last). Several selected pictures move, turn and size together, each by the same amount. A typed number in the Picture tab goes to all of them.

Only with the camera off

Editing happens on the stage's picture, which shows when the camera is off (step 15). With the camera on, the stage is live; the Picture tab's numbers still work there.

Watch out

  • Thumbnails don't show the transform. They're the photo as taken, so a moved or turned picture looks unmoved on the timeline. Rendering them through the renderer is a later improvement.
  • Number fields are controlled. Typing a lone "-" before a number is ignored until there's a number. The steppers and arrow keys work.
  • View zoom (looking closer at the stage) is step 19. Until then the stage is always fitted, which keeps the pixel maths simple.
  • The camera start in end-to-end tests is flaky under load. This step's full run had 3 setup failures, which passed on rerun (see the note below).
