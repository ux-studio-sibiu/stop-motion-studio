Camera

The studio can turn the webcam on and off, show its live picture on the stage, switch between cameras and remember the choice. Every way it can go wrong (blocked, no camera, busy, unplugged, insecure page) gets a plain sentence and the one button that helps. No pictures are taken yet; that's step 05.

What was built

  • src/adapters/camera/camera.ts: plain functions over the MediaDevices API. openCamera(), stopStream(), listCameras(), cameraPermissionGranted(), videoConstraints(), and cameraStatusFromError(), which turns a getUserMedia error into a status.
  • src/adapters/camera/camera.test.ts: 11 tests for the error mapping and constraints.
  • src/studio/useCamera.ts: the hook that owns the camera's lifecycle and exposes status, stream, devices, deviceId, start(), stop(), selectDevice().
  • src/studio/CameraView.tsx: the <video>. CameraMessage.tsx: what the stage says when there's no picture. CameraPanel.tsx: the side panel with the camera picker, on/off button and the (still disabled) capture button.
  • .icon-button.is-primary in _controls.scss, and the camera styles in studio.scss.

Decisions

Browser rules in the adapter, lifecycle in the hook

The roadmap first put a useCamera hook in adapters/. It was split instead: adapters/camera/camera.ts knows the browser (constraints, error names, device lists) and has no React, so it's unit-tested; studio/useCamera.ts knows React (state, effects, cleanup). The adapter can be reused by anything that needs a camera, like a future "import from phone camera" source.

No mirroring, and the preview is cropped like the photo

The plan said "mirror the front camera". It was dropped: the preview shows exactly what a capture will contain. A mirrored preview would make every photo look flipped compared to what the child just saw, and the onion skin (step 17) and alignment tools (step 19) only work if the live picture and the photos match pixel for pixel. The <video> uses object-fit: cover in the 16:9 frame, the same cover-crop step 05 will use when it captures, so a 4:3 webcam shows the crop it will really take.

Ask for permission after a tap

If the browser already remembers "allow" for this site (navigator.permissions.query({ name: "camera" })), the camera starts by itself. Otherwise the stage shows a big "Turn on camera" button, so the permission prompt appears right after the child (or the grown-up) asked for it, not out of nowhere. Browsers that can't answer the permission query just show the button.

Every open gets a request number

getUserMedia is slow and can resolve after the user has already turned the camera off, switched cameras or left the studio. Each open() takes a number; release() bumps it. When a stream arrives with an old number, it's stopped instead of shown. This is also what makes React Strict Mode's double mount in development safe: the first mount's stream is stopped when it lands.

src/studio/useCamera.ts

const next = await openCamera(id, SIZE).catch(...);
if (mine !== request.current) { stopStream(next); return; }   // a newer request, a stop or an unmount won

The chosen camera is remembered

The device id goes to localStorage (wrapped in try, so blocked storage just means "not remembered") and is requested with deviceId: { exact }. If that camera is gone, the hook forgets it and opens any camera instead of failing.

The camera turns off when the tab is hidden

When the child switches tabs, the stream stops and the camera light goes out; when they come back, it starts again (only if it was on). It's a privacy habit worth having in a kids' app, and it frees the camera for other apps.

Ask for the working size

Constraints ask for ideal 1280×720 (the default project size; the real project's size once projects load in step 07). ideal, not exact: a camera that can't do 720p still opens, at its closest mode.

Watch out

  • Stop every track. Clearing video.srcObject doesn't release the camera; only track.stop() does. The hook stops tracks on turn off, camera switch, tab hidden and unmount.
  • iOS needs playsInline and muted on the <video>, or Safari opens it fullscreen or refuses to autoplay.
  • Device labels are empty until permission is granted. The picker shows "Camera 1", "Camera 2" until then, and the list is refreshed after the first stream starts and on devicechange.
  • Unplugging fires ended on the track, not an error. The hook listens for it and shows "No camera found".
  • The secure-context rule. On a tablet opening the dev server by LAN IP over http://, navigator.mediaDevices doesn't exist: the stage shows the insecure message. Use next dev --experimental-https for that.
  • React's hook lint rules (react-hooks/immutability) reject a useCallback that calls itself. The "remembered camera is gone, open any" fallback is a .catch() inside the same call instead of recursion.

Check it

npm test
npm run dev
  • /studio: the stage asks to turn on the camera. Tap it, allow the prompt: the live picture fills the 16:9 frame, not mirrored.
  • "Camera off" in the side panel: the picture goes and the camera light turns off.
  • Block the camera in the address bar and press "Try again": the blocked message.
  • Open the camera in another app first (on Windows): the busy message.
  • Unplug a USB webcam while live: "No camera found".
  • With two cameras, the picker appears; switch, reload: the same camera comes back.
  • Switch to another tab and back: the light goes off and on.
  • Leave the studio with the back arrow: the light goes off.
Tested while building with a fake camera (a canvas stream in place of getUserMedia): idle → live, off stops the track, unplug → no-camera, denied, busy, a late stream from an older request is stopped while the newer one is shown, and leaving the studio ends the track. Not yet tested on a real webcam, a tablet or Safari: do that when reviewing.
