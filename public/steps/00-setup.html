Build steps · Step 00 of 32 · Part 1 Foundations

Setup

An empty Next.js project that builds to a static site, lints its own layering rules and runs tests, before any feature exists.

What was built

  • create-next-app@16.4.6 with TypeScript, App Router, ESLint and src/, no Tailwind. The demo page, its CSS module, the Geist fonts and the sample SVGs were removed.
  • next.config.ts: output: "export" and images.unoptimized.
  • sass for SCSS; src/styles/globals.scss with a minimal reset and two colour tokens (the real tokens come in step 01).
  • Empty layer folders, each with a one-paragraph README.md saying what belongs there (git doesn't track empty folders, and the note is the rule): core/, adapters/, store/, studio/, features/, styles/.
  • ESLint no-restricted-imports rules in eslint.config.mjs: src/core/** may not import React, Next, Dexie, Zustand or any other layer; src/adapters/** may import only from core/.
  • Vitest (vitest.config.mts) with the @/ alias, and one smoke test in src/core/setup.test.ts.
  • serve to preview the exported site with npm start.
  • These build notes: plain HTML in public/steps/, one page per step, served by the app at /steps/index.html.
  • STYLE_GUIDE.md (via scripts/sync-style-guide.ps1, with this repo added to its targets) and COMPONENT_PATTERNS.md copied in for standalone clones.

const coreRules = {
  files: ["src/core/**/*.{ts,tsx}"],

Decisions

Static export from day one

Everything this app does (camera, canvas, IndexedDB, encoding) happens in the browser. With output: "export", next build writes plain HTML/JS to out/, which any static host can serve. Turning it on now means anything server-only (API routes, server actions, reading cookies, dynamic routes without generateStaticParams) fails the build immediately instead of in step 32.

  • next start doesn't work with a static export, so npm start serves out/ with serve instead.
  • images.unoptimized: next/image's optimiser needs a server. Our images are Blobs from IndexedDB anyway, drawn with <img> or canvas.

Cache Components off

create-next-app 16.4 turns on cacheComponents and partialPrefetching. Both are about caching and streaming server-rendered data. This app renders no server data, so they were removed rather than carried as unused configuration.

Layering enforced by lint

PLAN.md §2 says core/ is framework-free. A rule in the README would erode the first time an import is convenient; an ESLint error doesn't. The rule is cheap to relax later if a layer needs it, and the message says why it exists.

Vitest, not Jest

Same describe / it / expect API, but it uses the Vite toolchain, understands TypeScript and ESM without configuration, and is fast. Tests run in Node for now: core/ has no DOM. Dexie tests in step 06 add fake-indexeddb; UI is checked in the browser.

Build notes as static HTML

Each step's notes are a hand-written HTML page in public/steps/, not a Next route or a Markdown file. Next copies public/ into the export as is, so the notes ship with the app, open without a build, and keep working even when a step leaves the app broken. They share one local stylesheet, steps.css, whose look is copied from effects-collection/index.html.

No Tailwind, no font yet

The workspace style guide is SCSS with nsc- roots. Fonts are a design decision for step 01, so the system font stack stands in.

Watch out

  • @types/node peer conflict. The scaffold pins @types/node@^20; Vitest 5 wants 22 or 24+. It was bumped to ^24. Don't install with --legacy-peer-deps to "fix" it.
  • "Cannot find native binding" from Vitest. npm can drop the platform binary of rolldown (Vite's bundler) from the lock file, a known npm optional-dependency bug; a clean reinstall only fixes it until the next npm install <pkg>. Since step 01 the Windows binary is pinned in optionalDependencies at rolldown's exact version, which npm skips on other platforms. When Vitest is upgraded, bump that pin to the new rolldown version; macOS/Linux contributors who hit the error add their own platform's binding the same way.
  • LayoutProps / PageProps are generated types. They exist only after Next writes route types, so npm run typecheck runs next typegen before tsc.
  • AGENTS.md is generated by Next. next dev rewrites its block, telling agents to read node_modules/next/dist/docs/ because Next 16 differs from older versions. Commit it as is.
  • Secure context. getUserMedia and crypto.randomUUID need HTTPS or localhost. Testing from a tablet on the LAN needs HTTPS (e.g. next dev --experimental-https), not just the IP.
  • Directory index in dev. next dev doesn't serve index.html for a folder, so link to /steps/index.html, not /steps/.

Check it

npm run lint
npm run typecheck
npm test
npm run build
npm start

Lint and the type check are clean, one test passes, and out/index.html exists. npm start serves it at http://localhost:3000, with these notes at /steps/index.html.

To see the layering rule work, add import { useState } from "react"; to src/core/meta.ts (from step 02 on: any file in src/core/model/) and run npm run lint: it fails with "core/ is framework-free". Remove the line afterwards.
