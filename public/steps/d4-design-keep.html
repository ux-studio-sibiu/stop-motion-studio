Keeping tweaks, and handing them over

Tweaks made in the token panel on /design now stay in the browser, through reloads, until Reset all. Copy changes puts them on the clipboard as a message to paste into the chat with Claude, which makes them permanent in the code.

What it does

  • Kept until Reset all: every tweak is saved as it's made and comes back after a reload. The count at the top covers both themes; the Tokens button shows it while the panel is closed. Reset all (asks first) clears them in both themes.
  • Copy changes copies, for example: 
    Design-system tweaks for stop-motion-studio: please make these permanent in
src/styles/globals.scss (light theme in :root, dark theme in the prefers-color-scheme block),
and in src/design-system/tokens.ts, so the token test keeps passing:
- --color-border (light): #b5ab9b -> #9d927f   (outlines of panels, controls and cards)
- --radius-small (light and dark): 0.625rem -> 0.5rem   (buttons, fields, tabs)
    Each line: the token, which theme, its value and the new one, and what it's for. Only real changes: a tweak set back to the token's value is left out.
  • Which theme a line is for follows how globals.scss works: a token the dark theme doesn't override has one value for both, so tweaking it in light changes both ("light and dark"); tweaking it in dark adds a dark override ("dark, a new dark override").

Decisions

  • The page's own storage key (stop-motion-studio:design-system-tweaks), read through a small store, not the studio's remembered.ts: the page stays stand-alone. Anything odd in storage is ignored.
  • Nothing is written to the code by the page. The permanent change is made from the message, in the chat; then Reset all clears the tweaks that are no longer needed.
  • The message is a pure function (changes.ts), the one thing here with a unit test.
