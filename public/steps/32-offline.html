Offline (PWA)

After one visit the studio is stored on the device: it opens, takes pictures, plays and saves GIFs and videos with no internet. The animations were already on the device (IndexedDB); now the app's own files are too. It can be installed like an app. Online, it's always the latest version: pages come fresh from the network, and the stored copy is only for when there's none. Only a page opened from the stored copy offers Update, when a newer version comes. The planned step 33, Ship, is dropped: the studio is already live at stop-motion.studiosibiu.com.

What was built

  • A service worker, scripts/sw.js, hand-written. npm run build now runs scripts/build-offline.mjs after next build: it lists the files in out/ and writes out/sw.js with those lists in front. It prints what it keeps: 68 files (1.8 MB), then 73 sounds (24.9 MB).
  • What's kept, decided in core/offline/precache.ts (plain TypeScript, tested; the build script runs the .ts file directly, and copies its pageKey into the worker, so the tested code is the shipped code):
    • the shell: the pages (stored as /, /studio, /design), the code, the fonts, the cardboard pieces, the icons and the manifest. Stored when the worker installs, all or nothing;
    • the sounds: fetched in the background once the worker runs (the page asks for it), and stored as they're played, in a cache of their own;
    • left out: these build notes (/steps/, always fetched fresh), source maps and the not-found pages.
  • Online first. Pages, and every stored file without a hash in its name (Next's page data, the manifest, fonts, cardboard pieces), come from the network; from the cache only when there's no network or it takes over 4 s. The code chunks (/_next/static/, a hash in every name, so a file there never changes) come from the cache first. Sounds from their own cache.
  • Versions: each list has a hash of its files' contents. A build that changes anything makes a new worker and a new shell cache; the new worker takes over at once and drops the old cache. A build that changes no sound keeps the 25 MB of sounds already stored.
  • The Update notice (src/offline/OfflineSupport.tsx, in the root layout): "A new version of the studio is ready." with an Update button, at the top of the page, only on a page opened from the stored copy. The worker notes each tab it answered from the cache; the page asks it on load ("served"), and if so, shows the notice when a newer worker takes over. Pressed, the page reloads, fresh from the network. The browser looks for a new worker on every visit, and the studio asks again when it's looked at again or the internet comes back.
  • The manifest (src/app/manifest.ts, written as /manifest.webmanifest) and the icons: the favicon's bars as PNGs in public/icons/ (192, 512, and a maskable 512 on the page colour), and src/app/apple-icon.png for iPads.
  • Settings (home page) says "The studio is saved on this device: it works without the internet too." once it is, and shows Install the studio when the browser offers it (Chrome, Edge; Safari installs from its Share menu instead).

Decisions

  • No PWA library. The usual ones (next-pwa, Serwist) plug into webpack; this build is Turbopack. The worker is about 90 lines and the lists come from the export itself, so nothing can be forgotten.
  • Online first, the cache as a fallback. Online, a child always gets the latest studio with no prompt to understand; the 4 s limit keeps a very slow classroom Wi-Fi from leaving them waiting (that page then counts as opened offline).
  • An update never reloads by itself. A child in the middle of an animation, opened offline, keeps that version until they press Update. The animations are saved as they change, so pressing it loses nothing.
  • Only in the production build. The dev server has no /sw.js, and a worker there would serve old files while editing. For the same reason npm start now serves on port 3100, not the dev server's 3000.
  • Tests block service workers, all but offline.spec.ts: otherwise every test would download the app and the sounds into its fresh browser.

Watch out

  • Stored files ignore their requests' Vary header and query: the server says Vary: Accept-Encoding, and scripts and prefetches don't all ask the same way; without it, some chunks weren't found offline.
  • A worker script answered from the cache is copied into a fresh response: Next's worker bootstrap reads its settings from its address's #params=, and a stored response would give it the stored address, without them (the GIF encoder failed with "Missing worker bootstrap config").
  • The host must serve pages at their clean names (/studio), as it does now; the worker stores them under those.
  • Offline right after the first visit, the sounds may not all be stored yet: one not stored yet plays as silence until the internet is back.
  • A page opened offline that stays open after a newer worker took over runs old code with the new cache: a part it hasn't loaded yet may be missing (a new deploy removes the old chunks). That's what the Update notice is for.

Check it

  • npm run test:e2e -- e2e/offline.spec.ts (builds the app, about 40 s).
  • By hand: npm run build, npm start, open http://localhost:3100, then DevTools → Application → Service workers shows it running; tick Offline in the Network tab and reload: the studio still opens and takes pictures.
  • On the live site after the next deploy: install it from the browser's address bar, turn the Wi-Fi off, open it.
Checked while building: lint and typecheck are clean; 433 unit tests pass; offline.spec (3 tests) passes against the production build, and the projects and storage specs (the Settings window) against the dev server.

Review checklist

  • npm run build prints the worker's line, and out/sw.js lists no /steps/ or .map file
  • offline after one visit, the studio opens, captures and exports
  • online, a new deploy shows on the next load with no notice; a page opened offline offers Update, and nothing reloads until it's pressed
  • npm run dev registers no worker
  • the install offer shows in Settings in Chrome, and the installed app opens in its own window
